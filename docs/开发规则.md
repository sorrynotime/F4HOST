# 开发规则

[返回文档目录](README.md)

本仓库以 `main` 为唯一主分支，后续开发都在 `main` 及其派生分支上进行，不再使用 `master`，也不再把 `master` 合并到 `main`。

## 分支流程

1. 开始一项功能或修复前，先把本地 `main` 更新到最新，再从 `main` 切出独立分支。
2. 所有代码、文档和配置修改都在该分支上完成；不直接向 `main` 提交未完成或未经验证的改动。
3. 在分支上完成编译和相关验证（见[编译、验证与维护](05-build-and-validation.md)），确认功能正常。
4. 验证通过后，先同步最新的 `main` 到分支并处理冲突，再把分支合并回 `main`。
5. 合并完成后删除该功能分支，并确认 `main` 仍处于可编译、可验证的状态。

## 约定

- 分支命名建议：`feature/<功能名>`、`fix/<问题名>`、`docs/<文档主题>`。
- 一个分支只处理一项功能或问题，避免把不同修改混在一起合并。
- 未验证、临时调试或实验性改动不得合入 `main`。
- 编译产物按仓库 `.gitignore` 管理，只保留 `.bin`、`.hex`、`.axf`、`.map` 格式，其他格式不要提交。
