# 上板调试与日志采集

[返回文档目录](README.md)

以下工程路径均相对于仓库根目录，执行命令前切换到根目录。

## 接线、运行与日志

1. 使用 `Msp/MDK-ARM/F4HOST.uvprojx` 编译下载，或使用本次生成的 `.build/armclang/F4HOST.hex`。固件地址为 `0x08000000`。固件需要另行下载到开发板。
2. 板子 PA2（USART2 TX）接 USB 转串口 RX，共地，115200、8 数据位、无校验、1 停止位。诊断直接使用 UART2 TXE/DR，因此 UART2 不能再同时用于其他 HAL 发送、DMA 或日志。
3. 保持工程既有 USB 接线：PA11 D−、PA12 D+；核对主机口 VBUS 有 5 V，PC9 的开关控制与板上电路一致。
4. 先打开串口记录，再上电/复位、插入接收器。初代按官方教程选择 PC 模式；二代按自己的说明书操作。
5. 等 CFG/HID/FIELD 输出完成。依次记录静止、每个按键单独按下、十字键四个方向、左右摇杆各轴两端、左右扳机。每个动作保持约 1 秒再松开，便于 100 ms 的日志采样捕获。
6. 拔掉接收器，再插回，确认 USB 状态变化、序号清零、旧按键清空。另测手柄关机但接收器不拔的情况，记录是否继续来包。

日志含义：

| 前缀 | 含义 |
| --- | --- |
| USB | Host 状态、VID/PID、配置长度；ABORT 表示未进入输入接收 |
| CFG | 配置描述符十六进制，带字节偏移 |
| PAD | 选中接口的 class/subclass/protocol、IN 地址、MPS、轮询周期、映射状态 |
| HID | HID Report Descriptor 十六进制，带字节偏移 |
| FIELD | Report ID、Usage Page/Usage、位偏移、宽度、逻辑范围 |
| RAW | 最新完整输入包、实际长度和序号；日志每 100 ms 最多采样一次 |
| AX | 同一采样序号的原始轴值，顺序为 X/Y/Z/Rx/Ry/Rz/Slider/Dial/Wheel |
| STATUS | 每秒显示 USB 就绪、解析有效、收包计数、解析计数、距最后一包的时间、错误数 |

`g_gamepad.state.buttons` 的 bit0..31 对应 HID Button Usage 1..32，尚未对应 A/B/X/Y。`axes_valid` 的 bit0..8 标记轴是否收到过值，轴的 min/max 见 FIELD。`hat=-1` 为中立/未知，0 为上，顺时针到 7。

`usb_ready` 只表示接收器 USB 链路已启用，`state_valid` 只表示解析状态可用，**两者都不是无线配对/手柄在线状态**。设备可能静止时不发包，也可能手柄断线后仍发接收器心跳，不能凭超时或有包就判定无线连接。上层控制还需要经实机确认的无线状态和失联策略。

## 日志阅读补充

- 日志中的 `PAD map` 就是 `descriptor_status`：1 表示建表成功，0 表示没有映射字段或厂商接口，−1 表示描述符不可用、解析失败或超出支持范围。
- `RAW` 的序号跳跃不一定是 USB 丢包：日志只采样最新快照，不能用它衡量实际回报率或保证捕获每次短按。
- `AX` 使用对应 RAW 采样时保存的状态。查看同一 `seq`，并结合轴有效位图及 FIELD 范围解释数值。
- 首包之前 `STATUS age_ms` 由初始时间戳 0 计算；先看 `seq` 是否大于 0。
- STATUS 约每秒输出，但描述符转储、待发日志和主循环调度可能延后输出，不是精确定时信号。
- 设备未成功初始化时，PAD 的零值不代表真实接口属性，优先查看 USB/CFG 和枚举状态。
- `USB state/enum` 是本工程枚举值，名称见 [usbh_def.h](../Msp/Middlewares/ST/STM32_USB_Host_Library/Core/Inc/usbh_def.h)，不要套用其他库版本的数值表。

## 故障排查

| 现象 | 先检查 | 下一步 |
| --- | --- | --- |
| 完全没有串口输出 | PA2→串口 RX、共地、115200 8N1、固件是否运行 | 复位并检查主循环；确认 UART2 没有被其他发送逻辑占用 |
| 有 STATUS，但插入接收器没有枚举进展 | VBUS 5 V、USB D+/D−、主机口接线、48 MHz USB 时钟 | 对照板级电路；源码 PC9 高电平表示使能，不依据代码注释猜硬件极性 |
| 出现 ABORT | CFG 总长、接口数量、每接口端点数及设备是否有支持的 Interrupt IN | 保存完整日志，判断容量、设备类和接口选择问题 |
| `class=03 map=-1` | HID 长度、完整 HID 描述符、解析能力边界 | 保留 RAW 和描述符，核对具体失败项 |
| `map=0` | 是否厂商接口，或所选 HID 没有手柄 Application 字段 | 查看其他接口；必要时指定 `GAMEPAD_INTERFACE_NUMBER` |
| `usb=1 seq=0` | 手柄是否配对、模式是否正确、IN 接口是否正确 | 可能需要厂商握手；必要时对比 PC 从插入起的 USB 抓包 |
| 有 RAW，始终 `valid=0` | Report ID、报告长度和映射状态 | 将动作与原始包逐一对应，不立即写死偏移 |
| 轴方向、ABXY 名称不符合预期 | 当前只保留 Usage，尚未做物理映射 | 逐个动作标定，再增加专用映射 |
| `err` 增加后 `usb=0` | STALL 清除失败或 URB 未完成超时 | 保存故障前后日志，重新插拔并复现 |
| 手柄关机后 `usb` 仍为 1 | 接收器仍插在主机上，这是可能的正常现象 | 记录关机前后包内容，查明无线状态报文 |
